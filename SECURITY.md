# Handling credentials and taxpayer data

Use synthetic records in public issues, fixtures and screenshots. Never upload apiId/apiKey values, SAT passwords, private keys, certificates or applicant documents.

These examples keep secrets server-side, block redirects, restrict API routes and omit raw responses from console output. They are not a full production security architecture. Python cannot guarantee secure erasure of strings in memory.

Report any discovered credential exposure through your established private CRiskCo support or security channel. Do not publish it in a GitHub issue. A public vulnerability reporting contact must be verified before release.
